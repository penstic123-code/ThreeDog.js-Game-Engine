# 2026-11-04 审查 B：渲染部分

审查对象：提交 8690e1ac，分支 review/render，只看不改。范围是 render/、sky、weather、water、terrain、vegetation、particles、engine.post、engine.shadows、engine.terms 和两种渲染方式。

**怎么验证的。** 写了一个临时测试页（已删，没提交），在软件渲染下跑。标"实跑"的结论有数字，标"读代码"的只读了代码、没有跑。

这台机器上 `renderer: 'webgpu'` 实际走的是 WebGPURenderer 的 WebGL2 后端，不是真 WebGPU。下面 H1 用到的程序缓存逻辑在两种后端共用，所以结论适用，但没有在真 WebGPU 上跑过。

## 结论

有三个高优先级问题，两个都实跑确认，第三个在低档设备上直接丢阴影。问题集中在两处：WebGPU 上程序缓存的键漏了 TSL，级联阴影有几条路径没走到。

## 高优先级

### H1. WebGPU 上程序缓存的键不含 TSL，不同的补丁画成同一个

- **位置：** `render/patches.js:205` 的 key，`render/patches.js:263` 的 `nodeKey`；几处生成 cacheKey 的地方只散列 GLSL：`render/terms.js:81`、`render/terms.js:99`、`render/effects.js:209`（风）、`modules/vegetation/look.js:72`。
- **什么坏了：** 程序键由补丁名和 cacheKey 组成，cacheKey 只跟 GLSL 走。两个补丁 TSL 不同而 GLSL 相同（或者都没有 GLSL）时键相同，three 复用先建好的节点程序。WebGL 上"同键不同代码"会报错（`clash()`），WebGPU 上一声不吭。
- **实跑，第一例（`engine.terms`）：** 平面上先 `terms.cloudShadow({ tsl: c => ({ directDiffuse: c.directDiffuse.mul(0) }) })`，像素 73 变 0，正确。再换成 `.mul(1)`，应该回到 73，实际还是 0。第二个 spec 的 TSL 根本没生效。`remove()` 回到内置版后恢复 73。
- **实跑，第二例（游戏自己的补丁）：** 两个材质都带 `{ name: 'tint', slot: 'color', tsl }`，一个红一个蓝，不写 cacheKey。两块都画成红色 `[255,0,0]`，蓝的那块错了。
- **读代码推出的同类情况：** 两个物种用同样的振幅、不同的纯 TSL 摆动，`engine.vegetation.color({ tsl })` 换 TSL 不换 GLSL，都会踩到。
- **修法（`render/patches.js`）：** 在 `nodeKey` 里把每个补丁 tsl 的身份（函数对象用 `idOf`，对象形式取里面的每个函数）也算进去。这个键只有 WebGPU 读，WebGL 不受影响，几处 cacheKey 都不用改。`sharedPatch` 已经保证同规格共用同一个补丁对象，不会多编译。

### H2. 关着阴影时建级联，再打开，太阳光变 3 倍

- **位置：** `render/cascades.js:98`。
- **什么坏了：** 构造时写 `l.castShadow = shadowsOn(e)`，注释说是"和总开关处理现有灯的方式一致"。但总开关早就改成只写 `renderer.shadowMap.enabled`，不碰 castShadow（`core/shadows.js` `switchShadows`），这行是旧做法的残留。阴影关着建出来的额外级联灯 castShadow 永远是 false。之后打开阴影，`frame()` 里 `show` 为真，这些灯变成可见的不投影平行光。CSMShader 的"不投影的灯"循环把它们当普通灯全量相加，所以满屏过亮，而且近处以外没有阴影。
- **复现（实跑）：** `engine.shadows.enabled = false; const h = engine.shadows.cascades(sun, { count: 3, low: { count: 3 } }); engine.shadows.enabled = true;` 额外两盏灯 castShadow 为 false，地面像素 48。正常建的是 16，正好 3 倍。
- **现实路径：** 玩家存的设置是阴影关，游戏开局建级联，之后玩家在菜单里打开阴影。
- **修法（`render/cascades.js:98`）：** 无条件写 `l.castShadow = true`。总开关和 `show` 已经管住了关的情况。

### H3. 低档设备上 cascades 退成一张不动的小图

- **位置：** `core/shadows.js:209`、`core/shadows.js:213`。
- **什么坏了：** 低档设备默认 `n = 1`，走 `if (n <= 1) return`，既不建级联也不放阴影盒。游戏自己的灯留着 three 默认的阴影相机（左右各 5 米），位置也不跟随。高档设备上看到 150 米的阴影，低档设备上只有世界原点附近 10 米见方有阴影，走开就全没了。

  `count: 1` 在所有设备上都一样。`tier()` 把名字带 Intel、UHD、Iris 的显卡都算低档，所以很多笔记本会中招。
- **复现（实跑）：** 软件渲染档位是 low，`cascades(sun, { maxFar: 150 })` 后 `handle.csm` 为空，相机在 (200,10,200) 时 `shadow.camera.right` 还是 5，灯还在 (10,30,10)。
- **文档：** recipe 45 写"低档设备得到一张图"，字面上没错，但没说这张图不跟随。
- **修法（`core/shadows.js` `ownCascades`）：** `n <= 1` 时内部挂一个 `gameBox`（跟随 focus、`extent` 取 `maxFar`、`snap: 'texel'`），`remove()` 和切回多级联时撤掉。引擎自己的太阳在 sky 下已有盒子，不用动。同时在 recipe 45 写明。

## 中优先级

### M1. 天气信号写在外观半边，文档说在状态半边

- **位置：** `modules/weather/weatherLook.js:103`，全仓库只有这一处写这两个信号；`docs/recipes/08-weather-sky.md:25` 写的是 "the weather state writes the last six"。
- **什么坏了：** 设计上"换掉外观半边，状态和存档照旧"（`engine.use(myRain(), { replaces: 'weatherLook' })`）。换掉之后 `uWeatherLight` / `uWeatherFog` 没人写，一直是 1 或停在换之前的值，游戏的灯和雾在暴雨里不变。`weatherLook` 还要求有 `sky`，所以没有天空的游戏也拿不到这两个信号。
- **另外两处不一致：** `new-game` 模板的 `look/` 没有读这两个信号，新游戏下雨时灯和雾都不变；`modules/weather/Weather.js:4` 的注释还写着"影响太阳强度、雾距"。
- **修法：** 把这一行挪到状态半边 `Weather.js` 的每帧更新，它们是状态的值，和外观无关。模板 `look/lights.js` 加上这两个信号，并改掉旧注释。

### M2. WebGPU 设备丢失没有处理

- **位置：** `core/page.js:49`，只监听画布的 `webglcontextlost`。
- **什么坏了：** WebGPU 后端不触发这个事件，引擎里也没有 `onDeviceLost`。设备丢失后 three 只打一条日志，之后的 render 全是空操作。`page.contextLost` 一直是 false，循环不暂停，也没有提示。画面冻住，游戏时间继续走。
- **修法（`core/page.js`）：** 在 WebGPURenderer 上接 three 的 `renderer.onDeviceLost`，走和 `webglcontextlost` 同一段：置 `contextLost`、发 `page:contextlost`、弹提示。WebGPU 不能原地恢复，提示语要写刷新页面。

### M3. `shadow.intensity` 不传给其余级联

- **位置：** `render/cascades.js:120`、`render/cascades.tsl.js:52`。
- **什么坏了：** `shadowParams()` 只复制 bias、normalBias、radius、blurSamples、autoUpdate，但它的注释说"灯上写的值是唯一来源"。`sun.shadow.intensity = 0.3` 只对第一级生效，近处浅、远处全黑，分界处有明显跳变。
- **实跑（WebGL）：** 三级的 intensity 分别是 0.3、1、1。WebGPU 那边的节点在首次构建时克隆一次，之后的修改同样传不过去（读代码）。
- **修法：** 两处都加上 `intensity: s.intensity`。

### M4. 级联的材质表强引用，流式世界内存只涨

- **位置：** `render/cascades.js:88`、`render/cascades.js:94`。
- **什么坏了：** `this.mats` 是普通 Map，`sceneVisitor` 只有 `enter` 没有 `leave`，从不删除。贴图着色的地形每块都克隆一份材质，带自己的色图（`modules/terrain/terrainTexture.js` 的 `copyPatches(base, base.clone())`）。区块卸载时材质和贴图被 dispose，但 Map 还抓着 JS 对象，贴图数据一起留下。走得越远占得越多，直到关掉级联。
- **修法（`render/cascades.js`）：** 在 `fit()` 里给材质加一次性的 `dispose` 监听，把它从 `mats` 删掉。`drop()` 和 `gameMaterials()` 的逻辑不变。

### M5. 有四处对 three 的改动没登记

硬规则 4 要求每处改动都进 `core/threePatches.js`。现在登记了九项，下面四处不在里面：

| 位置 | 改了什么 |
|---|---|
| `render/postWebGL.js:36` | 包住 chain 第一个 pass 的 `render`，这可能是游戏自己的 Pass |
| `render/postWebGL.js:94` | 替换 three 背景网格的 `onBeforeRender` |
| `render/patches.js:317` | 替换 `renderer.library.fromMaterial` |
| `render/backend.js:46` | 替换 `renderer.debug.onNodeBuilderCreated` |

**修法：** 各自 `notePatch`，写清关掉后丢什么；不能关的写明原因。同步 THREE.md 的表和 design.md 里的"九处"。

### M6. WebGL 上下文恢复后环境贴图可能是黑的

- **位置：** `modules/sky/environment.js:47`（`_envFrame` 只在 `skyKey` 变了才重建），`core/page.js:56`。
- **什么坏了：** 上下文丢失后渲染目标的内容没了，而 `page:contextrestored` 没有任何引擎代码监听。天空时间走动时键会变，下一次间隔到了能自愈；时间停着（固定时刻的场景）就一直是黑环境图，PBR 材质发暗。这条只读了代码，没实跑。
- **修法（`modules/sky`）：** 监听 `page:contextrestored`，把 `e.key` 清空，让下一帧重建。

## 低优先级

- **L1. 效果全关后显存不释放。** `active` 为假时走直出，但 composer（WebGPU 上是 pipeline）一直留到引擎销毁。1080p 下两张 4 倍 MSAA 半精度目标加深度，估算约 200MB。玩家在设置里关掉所有效果也拿不回来。修法：`_sync` 发现没有效果开着时释放目标，或者 `rt.dispose()`（下次用时会重新分配）。
- **L2. `engine.terms` 有两个够不到的情况。** 在 `createEngine` 之前调用 `applyEffects` 时 `te` 为空，材质不进登记表。`applyEffects(m, { patches: engine.terrain.patches })` 的 season 来自 patches 而不是 `season` 选项，也不进登记表。两种情况后来调 `engine.terms.season()` 都到不了这些材质，和文档"every material you passed to applyEffects"不符。另外 `false` 之后再 `remove()`，云影补丁排到列表末尾，和 lighting 补丁的先后可能变了。
- **L3. 目标物体有父级时两种渲染方式方向不同。** WebGL 用世界矩阵（`core/shadows.js`），WebGPU 的 CSMShadowNode 用 `light.target.position` 这个本地坐标（three 第 535 行）。`light.target` 挂在移动的父物体下时，WebGPU 上级联方向错。
- **L4. `gameBox.remove()` 会盖掉游戏后写的值。** `core/shadows.js:122` 恢复创建时存的相机边界。没传 `extent` 时盒子根本没改过相机，却仍会把游戏之后写的 `shadow.camera.left` 等改回去。只在传过 extent 时恢复就行。
- **L5. `uNight` 有两个同名的值。** `engine.uniforms.uNight`（白昼低于 0.3 开始）和天空穹顶自己的 `uNight`（太阳落到地平线下才开始，`modules/sky/frame.js:77`）曲线不同。写天空层代码的人读到的是后者，文档没区分。
- **L6. 游戏的 Pass 被销毁的规则前后不一。** `remove()` 特意不 dispose 游戏的 Pass，`PostFX.dispose()` 和 `_setBackend()` 却会。

## 逐题回答

**WebGL 和 WebGPU 一致吗，每个补丁都有 TSL 形式吗？** 引擎自带补丁都有两种形式，R49 把关，例外要写进 ALLOW 并说明原因。slots 表的节点列和实现同源。不一致的地方是 H1（缓存键）、L3（方向）和级联 bias（WebGPU 按级数放大，这是 three 节点的做法，注释里写了）。

**WebGPU 第一帧修法稳吗？** 稳。`r._animation.start()` 有 `_requestId` 守卫，重复调用无副作用，three 自己的 `render()` 第一行也是这样调的，所以只是把同一件事提前到记录帧号之前。两条注意：一是依赖 `_animation`、`_nodes` 两个私有字段，而 `_nodes?.` 带可选链、`_animation` 不带，字段改名时一个静默失效、一个每帧抛错。package 的 `^0.187.0` 只放开 0.187.x，风险可控，建议升级 three 时把这里列入必查。二是 `nodeFrame` 没有公开入口，私有访问绕不开。

**后期排序和融合还融合吗？** 融合。WebGL 上 `groupFuse` 按槽位把相邻的 fuse 效果并成一个 FusedPass，`reads: true` 另起一组，同组不变时复用程序。WebGPU 上靠节点嵌套变成同一遍。深度检查 `checkDepthOrder` 对融合组不生效，但 fuse 片段本来也读不到深度，无妨。

**关着还有开销吗？** 代码路径上基本没有：云影靠 uniform 分支跳过，默认 0 时不算噪声；没效果时不走 composer；游戏材质不打补丁。剩下的是 L1 的显存，以及 Color 背景每帧一个全屏四边形（为了和 composer 路径同色，有意为之）。

**模块材质能换外观、保留 shader 吗？** 能。terrain、water、vegetation、particles 都有 `material` 读写，设的时候按原样画，要留引擎效果就走 `applyEffects(m, { patches: engine.x.patches })`，文档写清了。引擎自己的材质换走时只 dispose 引擎的，不碰游戏的。

**云影按需只在明确要求时重编译吗，terms 对后加的材质有效吗？** 是。全仓库只有 `applyEffects` 和 `terms` 调用时才会改补丁；开关云影浓度只改 uniform，天气变化不触发重编译。后加的材质能拿到当前的 term；已有的通过登记表更新。例外是 L2，以及 WebGPU 上的 H1。

**四个新信号对吗？** `uViewDistance` 默认 600，Stream 优先用地形的视距，合理，写者和局限都有注释。`uNight` 没有天空和日历时是 0，`uDaylight` 保持 1，等于默认白天，合理。`uWeatherLight` / `uWeatherFog` 默认 1 合理，但写的位置和文档不符（M1）。四个信号都写进了 recipe，引擎内部用法也都对。

**销毁、改尺寸、上下文丢失？** 改尺寸没问题：composer 每帧跟随渲染器，WebGPU 的 pass 节点自己跟，级联在投影变化时重算。销毁：后期、级联、补丁阴影材质、环境贴图、粒子都释放了，问题在 M4。上下文：WebGL 有暂停和提示，缺 M6；WebGPU 缺 M2。

**阴影盒和级联在游戏自己的灯上都能用吗？** 常见情况都行：游戏每帧写 position、target 是玩家、target 不在场景里、预算和盒子叠加、`remove()` 恢复。灯不在场景根下、两者同时用、没开 castShadow 都有明确报错。不行的是 H2、H3、M3、L3、L4。额外的不投影平行光也能正确相加（CSMShader 有专门循环）。

- 没有跑全量测试和 `npm run check`，本次只跑了证明上述结论的临时页。
- 按要求只提交这一个文件，没有写 `docs/testing/runs.md`。
