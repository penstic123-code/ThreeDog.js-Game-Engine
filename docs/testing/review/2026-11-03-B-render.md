# 审查 B：渲染和外观系统（master cb85ad58）

范围：`packages/engine/render/`（两种渲染方式、backend.js、slots.js、fx/*.tsl.js、materials.js、effects/terms、后期链和色调映射槽）、`core/look/`、`core/styleParts.js` 和画风包计划、天空/天气/地面/植被外观、云影和季节覆盖、`packages/post-effects`、`threedog/tsl`、外观相关菜谱。
做法：只读代码和文档，没有开浏览器，没有跑测试（判断里引用的测试是读出来的，不是跑出来的）。

总的判断：底子是对的。一个 `defineLookPart` 撑起了全部外观部件；共享点分层、`manual()`、"直接写就让出"这三档已经统一。WebGPU 的部件统一登记在 `registerWebGPUPart`，缺了 `threedog/tsl` 只会报同一个错。问题集中在三处：
(1) 后期效果的入口还是太多，画风包里放后期也有两条路；
(2) 有几处地方，AI 写的普通 three.js 代码在 WebGL 上会被引擎悄悄弄坏，或者表现跟 WebGPU 不一样；
(3) 云影是"不装也付钱"，而且语义有错。

---

## 1. 后期效果：同一件事有 5 到 6 个入口（P11、P8）——最重要

**是什么**：往画面上加一道后期工序，现在能走的路有：
- 画风里写：`style.post: [...]`、`postAdd()/postRemove()`（core/styleParts.js:245-261）、画风 `plugins/` 导出一个 Pass（core/plugins.js:95）
- 游戏开局时写：`createEngine({ post: { name: bool } })`、游戏 `plugins/` 导出一个 Pass
- 运行中写：`engine.post.addPass / insertPass / removePass`（render/PostFX.js:142-185）、`look.post.add(effect)`（render/postLook.js:551）、`look.post.patch(name, glsl)`（postLook.js:523-533，会生成一个 fuse 效果）、`look.post.replace([...])`
- 整个接管：游戏自己的 EffectComposer 画画布，引擎就让出（render/ownFrame.js）；或者 `look.post.manual('chain')`

slot-map 计划第 62 行明确保留了 `addPass` 和 `look.post.add` 两条并行的路，理由是"look.post.add 能带参数和开关"。

**为什么要紧**：
- AI 第一次读文档，要先弄懂 addPass、add、patch 三者有什么区别，菜谱 52 也得三个都讲。
- 画风包计划（2026-11-03-style-bundle.md 第 3 节、迁移表最后一行）新增了"plugins 里导出 Pass"这条路，`style.post` 却没删。结果画风里放后期有两条路，**而且两条路的控制方式不一样**：`style.post` 里的 bloom 可以用 `look.post.set({ bloom: false })` 关掉；画风插件里的 ShaderPass 没有 `look.post` 的键，只能用 `engine.plugins.off('ink/10-paper')` 关。设置菜单想做"关掉画风的颗粒"，就得分两种情况写。
- **插件文件放不了两边都能跑的后期效果**：`shapeOf`（core/plugins.js:27-37）只认 Pass（WebGL）和函数（只在 WebGPU）。`{ name, create, node, params }` 这种效果描述同时有两边的写法，却不被认。插件要么只能 WebGL 用，要么只能 WebGPU 用。这和"同一个插件能单独用、也能放进几个画风包"的目标冲突，也和 P7"只写了一种渲染方式要报错"冲突：插件根本没有办法两种都写。

**具体场景**：画风作者写 `plugins/20-grain.js: export default grain({ amount: 0.05 })`（来自 @threedog/post-effects）。开局报错"不是可接受的形状"，作者只好退回去写 `style.post`。

**建议（在 PostFX/postLook 这一层统一）**：
- 运行中只留一个动词：`look.post.add(x)`。x 可以是 three.js Pass、节点函数、fuse 片段、完整的效果描述。`engine.post.addPass` 留作 three.js 写法的别名，内部就是同一个调用，菜谱只讲一条路。`look.post.patch` 并进 `add({ name, fuse })`。
- 插件形状加上"效果描述"（有 name，并且有 create、node、fuse 之一），插到 `look.post` 的画风层（主人记作 `style:<名>`），这样插件也能用 set 开关。
- 删掉 `style.post` 和 `postAdd/postRemove`，画风只用 plugins。也可以反过来，保留 `style.post`、不让插件导出 Pass。两种只选一种，选定后同一次改动里删掉另一种（P9）。
- 规模：中。

## 2. 普通 three.js 的改尺寸、改像素比，在 WebGL 上会把后期链搞坏（P1、两种渲染方式不一致）

**是什么**：`resizeMethods._resize`（core/canvasBox.js:53-62）先比 `renderer.getSize()` 和画布尺寸，相等就直接返回，不再调 `post.setSize`。EffectComposer 不会自己跟着 renderer 变尺寸。
- 游戏自己写了 three.js 常见的 `window.onresize = () => renderer.setSize(w, h)`，而且先于引擎的 ResizeObserver 执行：引擎一看尺寸已经对了，就跳过了 composer。composer 的两张渲染目标还停在旧尺寸，画面被拉伸或者变糊。
- 游戏直接写 `engine.renderer.setPixelRatio(2)`（core/adaptive.js:40 承认这是允许的写法，只会停掉自适应分辨率）：composer 的像素比没变，后期链还在旧分辨率上画，再放大到画布，结果是糊的。
- WebGPU 那边的 `pass()` 节点会自己跟随 renderer 的绘制尺寸（postWebGPU.tsl.js:671），所以**只有 WebGL 坏**。

**场景**：高档设备默认开 MSAA，后期链总是开着（第 4 条）。AI 照 three.js 示例写了一个 resize 处理，拖动窗口后画面变糊、比例不对，换到 WebGPU 又正常。AI 会以为是自己的代码有问题。

**建议**：在 `webglPost.render`（render/postWebGL.js:439）开头比一下 `renderer.getDrawingBufferSize()` 和 composer 目标的尺寸，不一样就调 `composer.setPixelRatio / setSize`。每帧只多两次数字比较。`_resize` 里的提前返回改成对照 post 自己记下的尺寸。规模：小。

## 3. 云影：所有有光照的材质每帧都付钱，而且把点光源也压暗了（P10、画面错误）

**是什么**：
- `syncPlainTerms`（render/terms.js:151-180）会给每个进场景的普通有光照材质加上 'clouds' 补丁。`look.cloudShadow.shadow` 默认是 0（coreParts.js:179），可 GLSL 里没有任何分支（effects.js:86-93、161）：每个片元都算两次 `threedogCloudLight`，一次给 directDiffuse、一次给 directSpecular，每次是两层值噪声、8 次 sin。没有天空、没有云的室内游戏也一样付这个钱，每种材质还多一个程序变体。
- 补丁放在 `lighting` 槽（slots.js:48：`lights_fragment_end` 之后），乘的是**所有直接光的总和**，不只是太阳。WebGPU 那边也一样（effects.js:162 乘的是 directDiffuse 的总和）。

**场景**：夜里的街道，`style.clouds.shadow = 0.5`。路灯（PointLight）照在路面上的光圈会跟着飘动的云噪声一明一暗，可云挡不住路灯。室内的火把同样会被"云"压暗。

**建议**：
- GLSL 里先 `float k = threedogCloudLight(...)` 只算一次，外面包一层 `if (uCloudShadow > 0.0)`。这是按 uniform 分支，整个画面走同一条路，基本不花钱，也不用重新编译。
- 只作用于太阳：WebGL 端改在太阳那盏平行光的那一项上乘（类似 `lightsPars + lighting` 的做法，或者用 `directionalLightShadow` 的位置）；WebGPU 端用 lighting 槽现成的 `direct(light, ctx)` 钩子，只对 `light.directional` 并且是太阳的那一盏乘。
- 规模：小（分支）+ 中（只作用于太阳）。

## 4. MSAA 让高档设备"什么效果都没开"也走整条 composer（P10）

**是什么**：引擎自己建 renderer 时总是传 `antialias: false`（core/Engine.js:111）；`PostFX.active` 只要开了 MSAA 就是 true（PostFX.js:108），而高档设备默认开 MSAA（Engine.js:194）。所以只要不是低档设备，每一帧都要：画进两张 4 倍采样的半浮点渲染目标、OutputPass 全屏画一遍。`direct()`（postWebGL.js:459）"不开效果就直接画到画布、不额外花钱"的设计，实际上只有低档设备才用得到。EffectComposer 的两张目标都是 4 倍采样，可只有画场景的那一张需要。

**为什么要紧**：设计说"不装的东西没有代价"。一个没有任何后期的游戏，在高档设备上也付了一个全屏 pass 和两倍的 MSAA 显存。

**建议**：没开任何效果时用画布自带的 MSAA。WebGL 的 antialias 只能在建 context 时定，所以要么开局按"有没有效果、什么档位"决定，要么接受"运行中切 MSAA 要重启"。另一个办法：只给画场景的目标设 `samples`（composer 建好后把 renderTarget2 的 samples 设成 0）。这件事要不要做，先问主人：要么接受"MSAA 能在运行中切换"的代价，要么改。规模：中。

## 5. 同一个 WebGL 渲染器，在不同档位上背景显示不同（两种渲染方式一致性）

**是什么**：postWebGPU.tsl.js:684-685 和 postWebGL.js:455 都写了：sRGB 图片当 `scene.background` 时，WebGL 直接画（`direct`）**不做**色调映射，WebGL 走 composer 和 WebGPU **都做**。按第 4 条，"直接画"只发生在低档设备或者关了 MSAA 的时候。所以真实的分界不是"WebGL 和 WebGPU 不同"（design.md 第 8 节和菜谱 56 第 174 行都是这么写的），而是"WebGL 低档和其他所有情况不同"。

**场景**：天空盒照片游戏，在台式机（MSAA 开，走 composer）上暗一些，在 Intel 核显笔记本（低档，直接画）上亮一些、颜色也不一样，设置菜单一关 MSAA，背景就跳一下。

**建议**：在 `direct()` 里给 sRGB 贴图背景也套上 Color 背景已经在用的办法（画成一个参与色调映射的背景网格），让 WebGL 两条路径和 WebGPU 统一。同时把 design.md 和菜谱 56 的说法改成"和普通 three.js 不同（有意为之）"。规模：小到中。

## 6. WebGPU 上"改参数不生效"的行为和 WebGL 不一致（两种渲染方式行为）

**是什么**：`webgpuPost.set`（postWebGPU.tsl.js:620-625）：只要改的参数全是数字或颜色，并且这个效果有对应的 uniform 节点，就只写 uniform、返回 true、不重建。可 `uniformsOf` 对**每个**数字参数都会建 uniform（第 592-594 行），不管 node() 实际用的是 `ctx.p.x`（uniform 节点）还是 `ctx.params.x`（普通数字，在建图时就固定成常量）。WebGL 那边，没写 `update()` 的效果，改参数就重建（PostFX.js:207），所以会生效。

**场景**：AI 写了 `{ name: 'tint', params: { amount: 0.5 }, create: ..., node: (input, { params, tsl }) => input.mul(params.amount) }`，然后 `look.post.set({ 'tint.amount': 1 })`：WebGL 上变了，WebGPU 上没变化，也不报错（P7）。另外，颜色写成十六进制数字（`color: 0xff0000`）会被当成 float uniform（第 580 行）。outline.js:133 为此专门绕了一圈，AI 自己写的效果大概率会踩这个坑。

**建议**：传给 node() 的 `ctx.params` 换成一个能记录"读了哪些键"的代理。读过的键改了就重建，只通过 `p` 读的键才走 uniform。十六进制数字的颜色参数，按参数名或者默认值提示"请写成 THREE.Color"。规模：小。

## 7. 后期 Pass 自动摆位：会自己画场景的 Pass 被放错位置（P1、P10）

**是什么**：`insertPass`（PostFX.js:165）只把 FXAA/SMAA/TAA 放进 'final'，其余一律放进 'hdr'，排在引擎自己的 RenderPass 后面。`RenderPixelatedPass`、`SSAARenderPass`、`TAARenderPass` 都会自己再画一遍场景，而且三者都没有能被正则认出的名字。`cls` 取的是 `p.name` 或 `material.name`，取不到就变成 'pass'，所以全部进了 'hdr'。

**场景**：AI 照抄 three.js 的像素风示例：`engine.post.addPass(new RenderPixelatedPass(6, scene, camera))`。画面是对的，但场景每帧画了两次，引擎画的那一次完全白费。有阴影时，`holdAfterScene` 只保证阴影图不重画，但场景本身确实多画了一遍。

**建议**：识别"会画场景的 Pass"：`p.scene === engine.scene` 并且有 `camera`，或者是 three.js 的 `isRenderPass`、`isRenderPixelatedPass`、`SSAARenderPass` 这几类。这类 Pass 放进 'scene' 槽，替掉引擎默认的场景渲染，再在 describe 里写一句。规模：小。

## 8. WebGPU 上 removePass 泄漏节点的渲染目标（真实 bug）

**是什么**：`removePass`（PostFX.js:179-185）先 `h._impl = null`，再调 `h._remove()`，目的是照 three.js 的习惯，不帮 Pass 做 dispose。在 WebGPU 上，`_impl` 不是游戏的 Pass，而是引擎记下的节点列表 `{ nodes, dispose }`（postWebGPU.tsl.js:645），里面是 `display.bloom / pass / texture` 建出来的渲染目标。引擎把它置空以后，这个效果已经不在列表里了，下次 sync 也就不会再 dispose 它。

**场景**：WebGPU 上，插件导出一个用了 `ctx.display.bloom` 的节点工序。设置菜单每次 `engine.plugins.off/on` 一次，就多泄漏一组 bloom 的 mip 目标，显存一直往上涨。

**建议**：只在 `_impl` 是游戏自己的 Pass（WebGL）时才置空；节点记录照常 dispose。规模：小。

## 9. 外观值的函数出错时被悄悄吞掉（P7）

**是什么**：`tick`（core/look/points.js:195-203）里写的是 `try { n = live(fn, ctx) } catch { n = undefined }`，接着 `Number.isFinite(n)` 不成立就跳过。函数抛错，或者返回 NaN，什么提示都没有，每帧都这样。可同一类的颜色函数（frame.js:75、124、129）和曝光函数（frame.js:137）出错时会直接抛出来。同一份"函数值合同"，出错的处理却有两种。

**场景**：`look.fog.set({ far: ({ state }) => state.boss.dist * 3 })`，在 boss 出场前 `state.boss` 是 undefined，雾距离不跟着变，也不报错。AI 只会以为是层叠出了问题。

**建议**：开发版里 warnOnce，消息里带上部件、键、出错信息，并说明"返回的不是数字，这一帧没生效"。三类函数值共用一个 `live()` 包装，出错的处理统一。规模：小。

## 10. "全局改 three.js"不止两处（P2 的标记不准）

**是什么**：design.md 的 P2 和第 12 节说"还剩两处全局改动"，`threePatches.list()` 里也只有两项（patches.js:489、patchNodes.tsl.js:98）。实际还有：
- `core/sceneDelta.js:32-51`：改了 `THREE.Object3D.prototype.add / remove`，整个页面生效，没有登记，也关不掉。
- `sceneDelta.js:71-90`：给每个进场景、带材质的物体装一个自己的 `material` 访问器。
- 渲染器实例上被套了一层 `render`（ownFrame.js:33）。它不在原型上，影响小，但同样没在 threePatches 里列出来。
- WebGL 后期链每帧会临时改用户的 `scene.background`（postWebGL.js:447、469），还会套一层场景 Pass 的 `render` 方法（第 350-359 行）。
后两项不算全局，但都属于"偷偷改了 AI 的对象"，describe 里看不到。

**为什么要紧**：P2 承诺"能在状态里看到、能关掉"。Object3D.add 的钩子是自动接入的基础，确实关不掉；但至少应该进 `threePatches.list()`，并在 THREE.md 的"全局改动"里写明。

**建议**：Object3D 的 add/remove 和 `material` 访问器登记进 `notePatch`，`off` 时报"这是自动接入的基础，关掉后 scene.add 不再被接入"。design.md 的 P2 改成"四处，其中两处可关、两处是自动接入必需的 🤝"。规模：小。

## 11. 色调映射的出口指错了路（P2、两种渲染方式）

**是什么**：`look.tone` 的 `noPatch`（coreParts.js:87-88）教 AI 去改 `THREE.ShaderChunk.tonemapping_pars_fragment`。这是整页范围、只在 WebGL 上有效的全局改动。可引擎已经有一个两边都能用的 'tone' 槽（PostFX.js:23-24，post-webgpu 测试第 35 行验证过像素一致）。

**场景**：WebGPU 游戏照着报错去改 ShaderChunk，没有任何效果。

**建议**：报错和 noReplace 改成先指 `look.post.add({ name: 'myCurve', slot: 'tone', create / node })`，然后再说 `renderer.toneMapping = …`。ShaderChunk 那条删掉。规模：小。

## 12. 外观 API：动词同名不同义，作者方法和使用方法混在一起（P8 简单）

**是什么**：
- `patch` 在不同部件上意思不一样。`look.sky.patch / look.surface.patch / look.wind.patch` 是**换掉**一个命名的 GLSL 函数；`look.materials.patch` 是**加上**一个命名补丁（按用途）；`look.post.patch` 是**生成一个新效果**。`look.post` 还另外有一个 `add`。
- "整块替换"有两套机制。天空是部件级的 `look.sky.replace(obj)`；植被和地面外观整个替换要用模块级的 `engine.use(x, { replaces: 'vegetation-look' })`（lookWind.js:97）；`look.ground.replace` 只换材质。design.md 第 4.2、4.3 节说只能有一个的插槽用 `replaces`，而 `look.X.replace` 是第二种写法。
- 雾"自己来"有三条路：`scene.fog = x`（引擎让出）、`look.fog.replace(fog)`、`look.fog.manual()`。lookFog.js:7 已经把三者合成同一条记录，但对外还是三条路。
- `LookPart` 上公开的方法有二十多个（part.js：set、patch、replace、manual、point、value、top、drive、driven、feed、tick、batch、write、ownerValue、extend、retract、restyle、has、resolved、remove、values……），AI 写游戏只需要前五个。剩下的都是模块作者用的，同样出现在 `engine.look.fog.` 的自动补全里。

**建议**：
- `patch` 只表示"换掉一个命名的钩子"。"加上一个东西"统一叫 `add`（`look.materials.add(name, patch, { roles })`、`look.post.add`）。
- 删掉 `look.fog.replace`：直接写 `scene.fog` 本来就会让出，`manual()` 是有意说明"我来管"。
- 天空整块替换也改成模块槽（`replaces: 'sky-look'`），或者在 design.md 里写明"部件级 replace 只用于贴图或物体这种小的整块"，并且只留一种写法。
- 作者方法挪到 `defineLookPart` 返回的作者句柄上，公开对象上只留 set、patch、replace、manual、value、point。
- 规模：中。

## 13. 写自己的天空：普通 three.js 写法没被接入（P1，可以妥协）

**是什么**：`scene.background = tex` 会被接入（frame.js:56，引擎的穹顶让出）。但 three.js 最常见的写法 `scene.add(new Sky())`（three/addons）不会被识别：引擎的穹顶照样画，两个天空叠在一起。AI 必须知道要调 `look.sky.replace(sky)`（lookSky.js:130）。slot-map 第 43 行写的"直接写 background 让出"只覆盖了贴图背景这一种。

**建议**：自动识别不现实，这一条可以算妥协。开发版里可以加一条提醒：场景根上新加了一个 `material.side === BackSide`、尺度远大于 camera.far 的物体，而 sky 模块还在画穹顶时，warnOnce 提示"要换天空用 look.sky.replace(obj)"。在 design.md 第 4.3 节写明。规模：小。

## 14. 关阴影时改写游戏灯光的 castShadow（P1，小）

**是什么**：`switchShadows`（core/look/shadowPart.js:26-43）在关阴影时，把每盏灯的 `castShadow` 设成 false，先存一份原值，打开时再写回去。关阴影期间游戏自己改了某盏灯的 castShadow，重新打开时会被旧值盖掉。其实 `renderer.shadowMap.enabled = false` 在两种渲染方式下都已经不画阴影了。

**建议**：如果只是为了 WebGPU 不建阴影节点，就在 WebGPU 上才这么做，并且写回时只写"引擎改过、之后游戏没再碰过"的灯（跟 lookSurface 的 REC 一样用快照比较）。规模：小。

## 15. 每帧的小浪费（P10，小）

- `watchOwned` 里每个归属记录的 `read()` 每帧都新建数组（frame.js:41-56：颜色的 `toArray()`、雾、背景、半球光……），`check()` 和 `mark()` 各调一次，大约每帧十几个短命数组。可以改成写进一个复用的 Float 数组，或者逐个字段比较。
- `insertPass` 会重建两次后期链（PostFX.js:169 的 `_add` 里 `_change` 已经同步过一次，第 172 行又同步一次）。在 WebGPU 上就是两次节点图重建。
- `updateSky` 每帧都对所有外观部件调一次 `tick`（frame.js:66）。没有函数值的部件会马上返回，可以接受。

## 16. 过时的注释和文档（P9）

- render/postLook.js:8 引用的 `core/look/dynamic.js` 不存在。
- render/PostFX.js:7、render/fx/postWebGPU.tsl.js:5 写的是"挂在全局变量上"，实际早就改成 backend.js 里模块内部的登记表了（backend.js:274-286）。
- render/postWebGL.js:321 写"composer 是内部细节，没有公开接口返回它"，可 `post.object()` 和 `post.targets()` 就是公开的（PostFX.js:117、128）。
- render/effects.js:66-67 说"旧的 pars/vertex 块留给补丁用"，函数块和旧块里的 uniform 声明重复了两份（例如 `threedog_clouds_pars_fragment` 和 `threedog_uniforms`）。可以统一成"补丁也 #include 函数块"。
- docs/plans/2026-11-03-slot-map.md:27 写"云影下一步改成对所有材质自动"，其实已经做了（terms.js:125-180）。
- design.md 第 8 节"环境光遮蔽、描边、景深、调色没做对比 ❓"已经过时：tests/specs/post-webgpu.mjs:25-38 对这几样都做了对比。不过除了 lut 和 tone 有逐像素检查，其余都只比"画面平均亮度相差 3% 以内"，这不能证明是同一张画面（AO 在 WebGL 上用 GTAOPass 另外渲染一次法线，在 WebGPU 上用深度重建法线，两边的算法本来就不同）。
