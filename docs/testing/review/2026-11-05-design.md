# Design review, 2026-11-05: what the engine blocks, and what it should stop blocking

Base commit `0c7a7e86`, branch `review/design-0.8`. This is a report: no engine or tool code changed. Every finding comes from reading the code. Nothing here was run in a browser, and no test was run. The only command run was `api-count`, for the name totals. Each finding is marked:

- **open**: stop blocking. Lower it to a hint, or remove it.
- **change**: the check has a reason, but it is wrong in shape or in reach. Fix it.
- **keep**: correctness or safety needs it, or it already yields.

The owner's rule, used for every judgment: do not hide three.js. The engine coordinates, gives tools and builds wheels. A rule exists only for correctness or safety. A limit on how AI writes is removed or lowered to a hint.

## Result in brief

The core design passes the four questions. `core/owned.js` already makes the engine step back when a game writes a three.js value, and no rule stops a game from writing plain three.js. The problems sit around the edges:

1. Four checks fail a game's `npm run check` for reasons that are not correctness: file size, doc passages, doc paths, and a stale generated map.
2. One check and one dev-time throw treat "no key bound" as a bug. A click-only game is a legitimate design.
3. Some refusals added or left in the sky are errors where the game would still run fine.
4. The game template's text states style preferences as rules, and sends the AI to the library before it writes anything.
5. The library lost all its WebGL versions, and two entries exist only in the backup.
6. The template's `scene.background` fix is not on this branch, and when merged it leaves a setting that does nothing.

Only R1, R18, R22, R33, R40, R51, R52 and R53 run there. The bare root `npm run check` also reads `games/*`, and of the other rules only R21 and R26 report on game code, as warnings. R2 and R6 read game code only to count uses. All other rules read engine, tools or examples only.

### `applyState`

- `core/UrlState.js:62`, `:65`: `fresh` and `wait` validation. `fresh` deletes saves, so being strict is a safety matter. **keep**.
- `core/UrlState.js:78`: a key no module handles is reported in `refused`, not thrown. This is the right shape. **keep**.
- B6, `core/UrlState.js:126`: `state-at` throws where every sibling refuses, and it fires in `_late`, after the save, position, time and weather were applied. The `state-value` fix text (`core/errorCodes.js:575`) promises nothing was applied, which is true only for `_expand`. **change**: use `_refuse`.
- B7, `core/UrlState.js:33`, `:61`: the key list is closed, so a game's module cannot take its own key, even though modules declare `stateKeys`. A game can still run its own code after the call, so this is minor. **open**, later: accept keys named by installed modules' `stateKeys`.

### Op shape checks

`core/thingOps.js:78` `goodPos` and `core/opsRun.js` `bad-position`: refuse non-finite numbers and short arrays, and accept a `Vector3`. Without them NaN goes into a save. They return a refusal instead of freezing gameplay. **keep**.

### `lib pull` renderer refusal

`tools/lib.mjs:262-263`, `lib/lib-check.mjs:37-40`: GLSL in a WebGPU game really does stop the game at start, `--force` copies it anyway, an unknown renderer lets the pull through, and `lib check` is not part of `npm run check`. **keep**.

- B8, `lib/lib-check.mjs:32`: `createEngine(cfg)` with the options in another file reads as `'webgl'`, a wrong guess that refuses a fitting entry. **change**: answer null unless the call's argument is an object literal.

### One more refusal, found on the way

- B9, `modules/gameplay/Interactions.js:339`, `:344`, `:438`: an interaction whose action has no key throws from the frame hook in dev, which **freezes gameplay**. The `use` op is also refused with `noKey` for the local player. A click-only game whose own pointer code runs the op is stopped twice. `isUnbound` (`core/Input.js:228`) accepts `optional: true`, but the module declares the action itself without it (`Interactions.js:57`). **open**: dev warning, and let the op run when code asks for it. The honest note in `describe()` (`:408-411`) stays.

## C. `world` data and plain values

`modules/world/persist.js:33-41`, called from `records.js:21`, `:75`. The check runs in dev only. It stops a three.js object, a function or a DOM element in a record. **keep** for saved records: a save really cannot hold them, and the failure would otherwise appear only after a load.

The easy path exists but is badly signposted. `world.present(kind, { build })` makes the model, `world.view(id)` returns it, and any game `Map` keyed by record id works.

| # | Where | Problem | Verdict |
|---|---|---|---|
| C1 | `records.js:21` | `{ save: false }` records are checked too, although they are never saved (`persist.js:97`) and cleared on load. A temporary record holding a mesh is harmless. | **open**: skip the check for these. The exception is a kind simulated with `worker: true`, since those records are copied. |
| C2 | `persist.js:29` | The message names two systems but shows nothing to copy. | **change**: add one line: `world.present('crate', { build: rec => mesh })`, then `world.view(id)` gets the mesh. |

### Should both renderers be kept in the library?

**Yes. Open.** The library today has 5 entries, all WebGPU only. The backup has 7, all WebGL only. `grass-sway` and `rain` exist only in the backup, so they left the live library altogether. The port changed each entry's file in place rather than adding a second form.

`--webgl` is a supported way to start a game, and the library works per entry, so a WebGL game now gets a refusal for every entry. That limits a supported route, and the backup is one folder that nothing reads.

Recommendation, needing no tool change: put the 7 WebGL entries back beside the 5 ported ones under `<name>-webgl` with `--backends webgl`, and add `grass-sway` and `rain` that way as well. `lib list webgl` then finds them and the refusal stays correct. Merging both forms in one entry is better, but only worth building if someone asks. Do not delete the backup until this is done.

### Template defaults that hide things

E5, `templates/game/picture/index.js:13`, `palette.js:7`. **On this branch the template still writes `scene.background`, so a new game with `sky()` hides the dome.** The fix, `040307cf`, is only on branch `worktree-agent-a9887933fe15a860e`.

That fix also moves the trap. It calls `setClearColor`, but `core/Engine.js:150` always leaves a `Color` on `scene.background`, and three.js uses that first (`three/src/renderers/webgl/WebGLBackground.js:55`). So `palette.background` stops doing anything: under a sky the dome covers it, and without a sky the base gray does. An AI that edits the palette sees no change and gets no message.

**change**: delete both lines and the palette key. The engine's base gray already gives that color. Leave one comment: `engine.scene.background = ...` takes over from the sky dome, on purpose, and `engine.sky.backdrop` is the option that keeps sky signals. Merge that instead of `040307cf`.

## F. API freeze

The final list is at the top of `docs/plans/2026-11-05-api-freeze.md`. The tests used:

- **Real duplicate, goes:** two engine entries for one thing (`rays.cast`, `engine.tick`, `player.object`), or an internal object with a public read beside it.
- **Convenient and hides nothing, stays:** the reason "three.js or Web Audio can already do it" no longer deletes anything. `engine.detach`, `engine.setPixelRatio`, `engine.has`, `engine.fps`, `audio.noise`, `noiseBurst`, `tone`.
- **The freeze list was wrong on the facts, stays:** `screenToGround()` works with no camera rig, and the method exists only with one, so a plain three.js camera needs the function. `nav.findPath` is the low layer under `characters.findPath`. `sky.sunHeight` is not `sunDir.y` once `orbit.tilt` is set. `engine.moduleStates` is not in `engine.modules`, and `core/Loading.js:48` documents it.
- **Tuning values do not go private:** `jobs.*`, `stream.unloadFactor`, `level.heightfield` and similar move to "unstable". Removing them takes a knob from a game for no gain.
- **"Throw when misused" narrowed:** a "cannot right now" answer is never a throw. `rigid.add*` returns null before Rapier loads, which startup code hits legitimately, and `world.add` returns null when a save removed the record (`World.js:80`). Both keep `| null`. Only `inventory.add` moves to the result shape, since a full bag is an everyday answer with a reason. Throwing is for a wrong argument only.

Totals: 1778 public names now (`api-count`); **30 names to delete, leaving about 1748**. 27 rename or shape rows, 15 unstable rows.
