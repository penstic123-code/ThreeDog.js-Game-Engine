# 0.5 验收：真实小游戏《提灯人》

- 日期：2026-11-04。引擎：0.5 接口冻结点（tag `freeze/0.5-api`，4f941421）。答题：Sonnet，限 60 分钟，对引擎没有背景。
- 项目：工作区 `acceptance-0.5`（分支 `acceptance/0.5`，提交 26904693），游戏在 `games/lantern`。原始记录：[2026-11-04-lantern-notes.md](2026-11-04-lantern-notes.md)。截图：[../field/2026-11-04-lantern/](../field/2026-11-04-lantern/)（除 05 外都是打包版经 preview 打开后截的）。
- 用户定的终点：只让严重问题（起不来、进度损坏、稳定可复现的崩溃）挡交付；验收通过就停。

## 结果：通过

题目每条都做到：第三人称、6 个萤火罐收齐开门、出门通关、3 个巡逻影子、死亡后从存档点重来、灯油耗尽时变暗且影子变快、开始（新游戏 / 继续）、Esc 暂停、死亡和通关画面、刷新后"继续"进度正确（萤火罐、灯油、存档点、开过的门、影子位置）、画质设置、打包后在浏览器里实际玩过。没做：声音、人物走路动画、手机触控。

**没有遇到严重问题。** 一个菜单回路 bug（死后点"回到标题"，影子又抓到玩家，死亡画面盖住标题）是游戏自己的代码问题（退出完成前先解冻了世界），答题者已修并补了测试。

| 指标 | 结果 |
|---|---|
| 首次能玩（能走动、能收集） | 约 11 分钟 |

| 查文档 | 约 19 次，全部找到；how 2、AI.md 1、菜谱 5、api 约 9、COMMANDS 1；读过一次源码确认 `addBlocked` 的 bounds 形状 |

| 自己写的测试 | 7 项（收集、开门通关、死亡重来、刷新继续、灯油耗尽……），全过；其中 2 项多页并行时失败过一次、单独跑通过（固定等待受负载影响） |

## 不挡交付的问题（记进 docs/design.md 第 14 节，0.6 处理）

| 问题 | 影响 |
|---|---|
| 任何 `addCircle` / `addBox` 碰撞体都会挡相机射线，没有"这个碰撞体不挡相机"的选项（`canopyHeight` 只管地形自带的树） | 森林里相机塌到玩家脸上，答题者卡了约 15 分钟，最后改用一条 `addBlocked` 规则 |
| `npm run shot -- /` 在 Git Bash 下被改写成 `C:/Git/`；shot 不能越过引擎的标题画面 | 要设 `MSYS_NO_PATHCONV=1`；游戏只好自己加 `?play` 参数 |

| api 页没写 `addBlocked` 的 bounds 形状 | 读了源码 |
| 截图文件夹 `shots/` 被仓库 .gitignore 忽略 | 截图不进提交 |
