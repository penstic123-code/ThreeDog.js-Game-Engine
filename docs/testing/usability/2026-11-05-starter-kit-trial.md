# 起步画面试验方案：有它和没它，比一道小题

要回答的问题：一份可以复制的起步画面（素材库条目 `bright-cartoon`），能不能让 AI 更快做出更好的画面，而且不让每个游戏长得一样。

这份文件只是方案，还没有跑。做这个条目的助手不跑、不打分，由协调者派新的助手来跑。

## 题目（原文照给，两组一字不差）

> 用 threedog 做一个小游戏《风车谷送信》，大约 15 分钟做完。
>
> 玩家是一个小邮差，第三人称走路。山谷里有一条小河、一座木桥、一架会转的风车和三户人家。玩家从邮筒拿三封信，分别送到三户人家门口。三封都送到就显示"送完了"，可以重新开始。
>
> 画面要明亮、清楚、像一部卡通片：一眼能看出路在哪、房子在哪，整个世界像同一个人画的，不要廉价低模感，不要灰蒙蒙。这个山谷要有自己的样子，不要像一个通用的模板场景。
>
> 不能下载或使用外部模型、贴图。用 WebGPU。做完在系统 Chrome 的真 WebGPU 上截图看过再交。

为什么选这道题：不是岛，玩法很小，时间可以花在画面上。风车、小河、木桥、邮差都不在起步画面里，所以有它的一组也必须动手做新东西，不能只是原样摆放。

## 两组

| | 有起步画面 | 没有起步画面 |
|---|---|---|
| 题目 | 上面的原文，后面多加一段（见下） | 上面的原文 |
| 素材库 | `THREEDOG_LIBRARY` 指向 `packages/starter-pictures` | `THREEDOG_LIBRARY` 指向一个空文件夹 |

有起步画面的一组多加这一段，不多说：

> 素材库里有一份起步画面，可以用，也可以不用。`threedog lib list` 能看到它，拉取后先读 `picture/index.js` 顶部的说明。

两组都要设 `THREEDOG_LIBRARY`。本机的 `~/.threedog/library` 里有其他条目，不设的话两组看到的不一样。

其他条件都相同：

- 同一个模型、同一个提交、`new-game` 默认模板，助手互不知情，也不告诉它这是对比试验。
- **每组至少跑 3 次。** 岛的两轮只差运气就差了 1.5 分，每组一次比不出东西。
- 分两批跑，每批两组各一次，免得机器负载偏向一组。
- 上限 25 分钟，到时间就交。超时的记下来，不重跑。

## 记什么

**时间和工作量**（每次一行）：

| 项 | 怎么量 |
|---|---|
| 总用时 | 助手从开始到交差 |
| 第一张能看的画面用时 | 第一次截图里有地面、天空、光影的时间 |
| 工具调用次数 | 运行记录 |
| 调画面的截图次数 | 运行记录 |
| 画面代码行数 | `picture/` 和 `main.js` 里画面相关的行 |
| 全流程能走通吗 | 从拿信到"送完了"，用脚本走一遍 |
| 真 WebGPU 能跑吗 | 截图输出写着 `drawn by WebGPU`，没有页面错误 |
| draw calls、三角形 | 和岛的记分表一样 |

**有起步画面的一组再记**：拉没拉；`threedog lib status` 说改过哪些文件；`paint.js`、`props.js` 改了没有；有没有留下 `sampler.js`。

## 画面怎么打分

1. 每个游戏拍三张固定的图：出生点、风车旁、桥上。系统 Chrome，真 WebGPU，1280×720，用游戏自己的相机。
2. 把图打乱，文件名换成字母，去掉界面文字里能看出分组的东西。
3. **打分的人不能看代码，不能知道分组。** 由用户看，或者派一个新的助手只看图。协调者跑过试验，不算盲评。
4. 每个游戏按下面五项打分，每项 0 到 2 分，满分 10 分：

| 项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 清楚 | 看不出路和目标 | 要找一下 | 一眼看出来 |
| 统一 | 各部分像拼来的 | 大体一致，有一两处跳出来 | 像同一个人画的 |
| 做工 | 切面明显、边缘脏、影子有噪点 | 有小毛病 | 干净 |
| 光和颜色 | 灰、平、过曝 | 还行 | 明亮，有明暗层次 |
| 自己的样子 | 像通用模板 | 有一些特点 | 记得住，不会和别的弄混 |

**长得一样不一样**，单独看，这是这个试验最担心的事：

- 把有起步画面的几个游戏和 `docs/testing/field/2026-11-05-starter-kit/overview.png` 放在一起，问打分的人："哪些看着是同一个游戏，或者同一个模板做的？"
- 没有起步画面的几个游戏也问一遍，当作对照。
- 记下相似的组数。

## 怎么下结论（跑之前先定好）

- **有用：** 有起步画面的一组平均分至少高 1 分；总用时不比另一组长 20% 以上；"自己的样子"一项不比另一组低；相似的组数不比另一组多。
- **有用但有害：** 分高了，但几个游戏看着像一个模板。这不算成功，要先改说明或条目，再跑一次。
- **没用：** 分差不到 1 分，或者助手根本不去拉。没人拉的话，题目和入口的问题要和条目本身分开看。
- 每组只有 3 次，这只是方向，不是统计结论。写结果时要这样说。

## 已知的不公平

- 题目要求明亮卡通，正好是这个条目的画风。这里测的是"合适的时候有没有用"，不是"什么时候都有用"。要测换画风，得另出一道暗色的题。
- 有起步画面的一组多了一段提示，这本身也提醒了它要重视画面。如果差距很小，要考虑是这段话的作用。
