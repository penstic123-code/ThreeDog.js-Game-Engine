# 《海风小岛》两轮对比（0.7，WebGPU 默认）

- 日期：2026-11-05。题目见 [../usability-tasks.md](../usability-tasks.md) 第三题，原文照给。两轮都用 Sonnet，互不知情，同一份 master（546d49e1），`new-game` 默认模板。
- 第一轮：画面只能用 three.js 和 TSL，不能用 `celLighting`、`@threedog/post-effects`。第二轮：没有这条限制，也没有提示要用。
- 截图和两份原始反馈：[../field/2026-11-05-island/](../field/2026-11-05-island/)。截图在真 WebGPU 上重拍（系统 Chrome，NVIDIA Blackwell），1280×720，游戏自带跟随相机。
- 评分是协调者看图和读代码的判断，不是真人盲评，每边只跑一次。

## 结论

**这两轮比不出视觉函数的价值。** 第二轮一个视觉函数都没用，所以两轮条件实际相同，差别只是单次波动。真正的结论是：AI 不会主动发现这批函数。

两轮都从开场走到结局，都在真 WebGPU 上运行，没有页面错误。AI 写 TSL 在这道题上是通的：水面、草和树的摆动都用 TSL 写成。

## 画面判断

- **第一轮：** 颜色饱满，圆润的树和花草更接近“高质量风格化”，海水有层次，小屋和人物读得清楚。缺点是饱和度偏高，光柱有硬边像玻璃条，路面边缘模糊。
- **第二轮：** 色调柔和、舒适，路径引导更清楚。缺点是树和石头的多面体切面明显，题目明确不要廉价低模感；海面的白点太规则；整体偏灰淡。
- **两边共同问题：** 跟随相机穿进树冠和屋顶；影子边有网点。

## 反馈的根因

| 根因 | 证据 | 修法 |
|---|---|---|
| 无头验证流程不顺（两轮用时最多） | 暂停页面走不动、标题挡操作、存档污染、`inputLocked` 不说原因 | 通关测试写法、原因写进结果、干净开局 |
| 脚本移动玩家没有直达说明 | 两轮都自己摸索上船和爬楼，船站不住 | 载人例子，`how` 能搜到 |
| 已有能力找不到 | `toast`、计数读取、`time.now`、TSL 名字、视觉函数 | 补索引和模板说明 |
| 诊断误导 | 无关的 `frozen-definition`、TSL 类型误报、WebGL2 后备没提醒 | 收紧匹配，截图写明后端 |
| 相机穿进场景（看图发现） | `r1-hill.png`、`r2-cabin.png` | 相机臂修复 |

修复之后用第三轮验证，看同样的卡点是否消失、AI 是否会用视觉函数。

## 小题复测（只测卡点）

修复后用小海湾题验证，Sonnet，约 10 分钟，31 次工具调用。题目写用户会提的需求，不点接口名。反馈：[r3-cove-feedback.md](../field/2026-11-05-island/r3-cove-feedback.md)。

| 卡点 | 结果 |
|---|---|
| 无头测试 | 过：从开始到拾取的脚本连跑 3 次，9/9 |
| 存档污染 | 过：没再出现 |
| 标题挡操作 | 过：`inputLocked` 带原因和修法，还要等几帧，约 3 分钟 |
| 弹提示、计数 | 过：`toast`、`hud.value` 一次用对 |
| 视觉函数 | 过：靠菜谱 56、52 找到 `celLighting`、`outline`。题目写了明暗分层和描边，所以这只说明需求明确时能找到 |
| 载人 | 部分：能用，但没用 `characters.support`，每步直接改位置 |
| 相机 | 没验证：树和小屋是手写网格，要自己登记才挡相机 |
