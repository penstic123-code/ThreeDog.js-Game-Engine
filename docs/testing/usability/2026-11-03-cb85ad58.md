## 自动检查

- 天空用 `engine.look.sky.replace(dome)` 接入，不是藏起引擎的天空再画一个。✅
- 体积雾用 `engine.look.post.add(...)` 接入，一个效果同时带 GLSL 版和 TSL 版。✅
- 画质菜单：玩家关掉阴影、体积雾以后，快进到别的时刻不会被重新打开（答题者用脚本测过）。阴影走引擎自带的设置；体积雾靠内部接口才做到（见"绕路"）。🟡
- 没有发现绕开引擎直接改雾、曝光、灯的地方；读了一次 `engine.scene.fog.color` 拿来给自己的雾配色，只读不写。✅
- **引擎有没有挡住 AI**：没有发现引擎把 AI 直接写的 three.js 改掉或拦下。但有两处"不得不用内部接口或绕开"：画质菜单限制自写效果、类型检查。这两处算引擎的问题。

## 按根因归类

| 类别 | 卡点 | 怎么修 |
|---|---|---|
| 机制缺口 | 游戏自己的设置项想"限制"一个效果（玩家关掉后场景不能再开），没有公开写法，只能用内部的 `stacks.take` | 设置项加一个公开的"限制哪个值"的写法，走设置层；报错和菜谱里指过去 |
| 报错没讲清 | WebGPU 着色器构建出错（`Cannot read properties of null (reading 'build')`）不写是哪个补丁、哪个插槽；GLSL 那边会写 | WebGPU 一侧也按补丁名、插槽名报错 |
| 报错没讲清 | TSL 的 `Loop` 写在 `Fn` 外面时语句悄悄丢失，没有报错（three.js 自身行为） | 菜谱 56 的"常见错误"写明；能检测时开发期警告 |
| 文档找不到 | `how "custom sky"`、`how "volumetric fog"` 没有有用结果；"读深度的后期效果（两种渲染器）"没有菜谱 | how 加同义词和条目；补一篇"读深度的后期效果"菜谱，GLSL 和 TSL 两版 |
| 接口名字误导 | `createEngine({ renderer: 'webgl' })` 报错，只认 'webgpu'；`post: { bloom: true }` 只能覆盖画风里已有的效果；`views.define` 用 `position`，而截图命令用 `--pos` | 接受 'webgl'；后期只留一个入口时一并理顺；名字统一 |
| 机制太复杂 | 游戏模板的类型检查对普通 three.js 写法报错（给对象后加字段、ShaderMaterial 和 NodeMaterial 的联合类型、内部接口不在公开类型里），答题者只好整文件关掉检查 | 公开类型补齐；模板的类型检查对游戏代码放宽到"不妨碍普通写法" |
