# threedog 引擎设计（唯一的设计文档）

> 这份文档写的是引擎**应该是什么样**，依据是用户本人的想法（2026-10-31 到 2026-11-03 的多次讨论）。其他设计稿（`docs/plans/` 里的画面架构、玩法架构、"主人"设计稿等）只是这里某一部分的展开，和这里冲突时一律以本文为准。
> 每一条后面标着现状：✅ 做到，🟡 部分做到，❌ 没做到，🤝 有意妥协（附理由），❓ 待复审核对。复审拿本文当尺子：逐条对照代码，修正现状标记，指出哪些该改、哪些可以妥协。
> 最后核对：2026-11-03 夜，master `469020b1`。依据是当天的三份代码审查（`docs/testing/review/2026-11-03-*.md`）和之后合进来的修复，每条都对照过现在的代码。不是 ✅ 的条目都写明了缺什么、算合理妥协还是要接着做。

## 1. 一句话

**引擎是一块带很多插槽的底板。AI 用 three.js 写代码，引擎自动或半自动地把它接进来，和引擎原有的东西一起工作，而不是去取代引擎。**

three.js 是画笔，引擎让很多支画笔同时在一张画上画而不互相涂掉，并且出了问题能查出是哪一支画的。

## 2. 为谁做

- **主要使用者是 AI 编程助手**，用户本人不写代码。所以"AI 第一次看就能用对"是最高优先级之一。
- 目标是**中大型网页 3D 游戏**，不限玩法和画风：慢生活、动作、射击、生存沙盒、横版，都要能做。
- 三件事都要：**做得快、效果好、AI 特别擅长**。要取舍时先问用户。

## 3. 原则（不能违反）

| # | 原则 | 具体意思 | 现状 |
|---|---|---|---|
| P1 | **three.js 永远可以直接写** | AI 随时可以用原生 three.js 写灯、材质、shader、贴图、后期、模型，写了就生效，永远不和引擎冲突。引擎的功能只是可选的捷径，从来不是唯一的路 | 🟡 基本做到 ✅：`scene.add` 和 `engine.add` 一样被接入；灯、雾、曝光、背景直接写时引擎让出；游戏自己的 EffectComposer 画整张画布时引擎让出，小地图这类只画一块的不算接管；OutputPass 之后的 Pass 放在色调映射之后；后期跟着渲染器自己改尺寸；游戏灯的阴影刷新交还（守卫测试 `tests/specs/plain-three-respect.mjs`、`plain-three-adoption.mjs`）。还差：`scene.add(new Sky())` 不会被认出来，两个天空会叠在一起，要用 `look.sky.replace(sky)` 🤝（引擎猜不出哪个物体是天空；菜谱 54 的对照表写明了这条路）；关阴影时引擎改写各盏灯的 `castShadow`，关着期间游戏自己改的值会被盖掉，要接着修（小） |
| P2 | **不遮住 three.js** | 引擎给出的对象就是原生 three.js 对象；命名跟 three.js 和网页标准一致；不悄悄改 three.js 的全局行为 | 🤝 射线的全局改动已去掉 ✅；引擎对 three.js 的改动一共九处（整页四处，按物体 / 渲染器五处，见第 12 节），全部列在 `describe().threePatches`（`core/threePatches.js`），七处可以关掉、两处写明了为什么关不掉。合理妥协：three.js 没有按物体挂钩的办法，自动接入要靠它们 |
| P3 | **不限制 AI 的发挥** | 凡是影响外观的，都有出口：调数值 → 往插槽加代码 → 整个换成自己的。AI 做不出某个效果，不能是因为被引擎卡住 | 🟡 天空、地面、植被外观、后期链都能整个换 ✅（后期：`look.post.replace`、`look.post.manual('chain')`、或者自己的 EffectComposer）；粒子可以用 `replaces` 整个换，契约（`modules/particles/contract.js`）保证换上的模块有内容要用的方法 ✅。水只能换材质，网格和跟随是引擎的；想整块自己画，就不装 `water()`，水位和水体数据留在引擎里照样能读（菜谱 44 "your own meshes"）🤝，可以接受，因为另一条路不卡人 |
| P4 | **three.js 能做的，引擎不再做** | 有了就最多在文档里指个路。引擎只补 three.js 没有的：跨系统协调、难写的工程、让 AI 看得见查得出 | 🟡 材质用途只剩一个入口 `look.materials`（画风的材质表是它的画风层，`makeMaterial` 只读它），普通 three.js 材质照样拿到雾、阴影、云影 ✅；灯池保留 🤝（"很多光源、只有几盏真灯"这个取舍引擎猜不到，普通的灯照样自动接上）；画风材质表里的 `{ type: 'toon', steps }` 写法和直接 `new MeshToonMaterial` 并行 🤝（只是画风层的简写）；没开任何效果时用画布自带的抗锯齿，不再自己做 ✅（2026-11-03） |
| P5 | **引擎不带美术，不做成品外观** | 没有默认画风、默认人物、默认地形长相；没给时只有中性灰的占位并提示。不提供"一键水彩""木头石头画家"这类成品，以免所有游戏长得一样 | ✅ 守卫测试 "the engine ships no art"（`tests/specs/art-shapes.mjs`）通过；low-poly 画风包已删 |
| P6 | **通用，不为某一个游戏定设定** | 默认值、参数名、按键、界面都不能按某一类游戏来定；只适合一类游戏的东西要么改成通用设计，要么挪到示例里 | ✅ 模块专属的默认键已删；三份审查都没找到按某类游戏定的默认值（交互的拾取要求游戏自己选） |
| P7 | **永远不悄悄出错** | 冲突、缺依赖、只写了一种渲染方式、写错选项，都要当场报错，并在报错里写明违反了哪条规则、照抄哪一行能改好。发布版不报错，但要记一条警告 | 🟡 共享值冲突、模块类型、缺依赖、按键、控制权 ✅；审查找到的静默出错都已修：设置层往上调会报错、读档后旧句柄照样能撤、外观值的函数抛错或给出 NaN 时警告并保留上一个好值、WebGPU 上改参数会重建效果、物理开局前加刚体会报错、契约漏的方法有规则 R50 拦。还差：没写 `type` 的模块放进 `plugins/`，报的是"不是插件"而不是"模块缺 type"（小，要修）；`lib pull` 拉下来的工厂函数放进 `plugins/` 会在开局报错，只靠拉取时打印一句提示（中，要修） |
| P8 | **简单** | 每件事只有一种做法；用到的词少（set / mul / add / replaces / type / requires / provides）；机制统一，不为每个模块另起一套 | 🟡 外观接口收窄成六个动词 ✅：每个外观部件都只有 set / patch（只表示换命名钩子）/ add / replace / manual / value，模块作者用的方法挪到 `part.author`（2026-11-03，守卫测试 `tests/specs/look-api.mjs`）。还差："谁说了算"有四套机制（共享点、引擎让出、角色控制、按键场合），AI 查"为什么是这个值"要看 `describe()` 的好几个地方，`owned` 和 `shared` 有重复。角色控制和按键场合本来就不是"合成一个数"，内部分开可以妥协，但查询应该统一成一处（中，下一版） |
| P9 | **过时的就删** | 新做法替换了旧做法，就在同一次改动里删掉旧代码、旧文档、旧选项、旧测试，不留兼容层（0.x 阶段）；破坏性改动写进迁移说明 | ✅ 本轮删掉：后期的五六个旧入口、`style.post`、`createEngine({ post })`、`look.fog.replace`、`look.materials.patch`、`time.manual`、模块的 `presentation` 字段、0.2 改名留下的报错陷阱、low-poly 画风包；每一项都写在 `packages/engine/docs/MIGRATING-0.4.md`，用旧写法会当场报错并给出新写法 |
| P10 | **不臃肿、不拖性能** | 不装的东西没有代价；每帧有时间预算；有性能门槛测试 | 🟡 云影关着时不花钱 ✅；没开效果时用画布自带的抗锯齿，不走整条后期链，显卡时间省约四成 ✅；临时物体移出场景后登记表放手 ✅。还差：引擎让出检测每帧新建十几个短命数组（小）；开着效果时 WebGL 每帧多约 0.15 ms 🤝（见第 12 节） |
| P11 | **同一件事不留两套平行的写法** | 一件事只有一个入口；画风包和插件走同一条路，同一个插件能单独用、也能放进几个画风包 | 🟡 已经是一条路的 ✅：材质用途一个入口；**画风包 = 一捆外观插件**，经 `engine.plugins` 插上（守卫测试 `tests/specs/style-bundle.mjs`）；**后期效果一个入口** `look.post.add`，游戏代码、插件文件夹、画风插件都走它（守卫测试 `tests/specs/one-post-entry.mjs`）；自己的雾只有 `scene.fog = ...` 一条路；材质补丁用 `look.materials.add`；时间速度只经共享点；模块分类只看 `type`。还差：模块"开始跑了没有"有 `engine.phase` 和内部的 `_started` 两个标记（小，要么合并，要么在架构文档里写清关系） |

## 4. 结构：底板、插槽、插件

### 4.1 底板分四层

| 层 | 内容 | 能不能不要 | 现状 |
|---|---|---|---|
| 核心 | 主循环和**单一时间来源**、事件、按键、存档、**生命周期**、**共享点和插槽**、状态查询（describe）和报错、两种渲染方式的启动、资源加载 | 不能，这就是底板 | 🟡 大体统一过 ✅；"谁说了算"的四套机制见 P8 |
| 工程模块 | 光影协调、天空天气昼夜、地形数据和分块加载、物理、寻路、角色和控制、相机、声音、界面焦点、联机 | 按需安装，外观部分都能换 | 🟡 地形、植被、天气已拆成"数据 + 外观" ✅，地形的数据部分不再读画风（颜色和远景雾在地形外观里）✅；水的数据（水位、水体）在核心、外观在模块 ✅，但网格不能换（见 P3）🤝；粒子是一个外观模块，有契约 ✅。声音和角色动画还没有"换成自己的"插槽（见第 14 节） |
| 玩法功能 | 背包、任务、对话、触发区、交互、过场 | 都是功能位，可以换成自己写的 | 🟡 `provides` / `replaces` / `requires` 都能用，背包契约已补全，引擎对可替换模块的调用必须在契约里（规则 R50）✅。还差：内容加载器写死了 15 个模块和它们的数据格式，自己写的模块没法登记"我认内容里的哪一段"，换掉任务、对话后内容照旧按引擎版的格式喂进去（大，和编辑器一起做）；背包、任务自带窗口和开关键，可以用 `engine.ui.set('inventory', false)` 关掉换自己的界面（菜谱 03）🤝 |
| 不归引擎 | 具体的美术、成品外观、游戏规则 | 归 AI 和游戏，可以放进个人素材库复用；画风包是游戏自己的一个文件夹（初始值 + 每种用途的材质 + 外观插件），low-poly 画风包已删 | ✅ 素材库 `threedog lib` 已做，读不了的条目会列出来 |

### 4.2 插槽分两种

- **能插很多个的**（绝大多数）：场景里的物体和灯、材质插槽、后期链、公共画面值、玩法里的公共数值、事件、按键动作。AI 写的东西往上插，和引擎原有的东西共存。
- **只能有一个的**（少数）：天空、地面外观、植被外观、色调映射、相机、各个功能位（背包等）。AI 要用自己的版本时，用 `replaces` 替换掉引擎原来的那个。
- 整块替换按大小只有一种写法：只换部件画出来的**那一个东西**（贴图、天空物体、某个用途的材质、一种粒子），用 `look.<部件>.replace(东西)`；连行为、存档一起换**整个模块**，用 `engine.use(mine(), { replaces })`。`replace` 不收模块，`replaces` 不收 three.js 东西。✅（植被外观是整个模块，所以用 `replaces`，不算第二套写法）

### 4.3 接入分三档，越自动越好

1. **自动**：引擎能从代码里看出来的，AI 不用多写一行。例如往场景加物体、加灯、改雾、改背景。✅ 改雾、改灯、改背景会让出；加物体、加灯自动接上；插件文件夹里的文件开局自动插上（一个 Pass 放进 `plugins/` 也是）
2. **半自动**：引擎看不出意图的，AI 写一行声明。例如"我在雾浓度上乘 1.4"（`mul`），"这是一个画面类模块"（`type`），"把这个 Pass 加进后期链"（`look.post.add(pass)`）。✅
3. **替换**：只用在只能有一个的插槽。✅（自己写的天空物体引擎认不出，要用 `look.sky.replace`，见 P1 🤝）

### 4.4 插件长什么样

- 简单的东西就是**原生 three.js 对象**，不需要包任何外壳：一个物体、一个材质、一个后期 Pass。
- 复杂的东西写成**模块**：声明类型（`type`）、提供什么（`provides`）、需要什么（`requires`），引擎帮它接好生命周期、存档、按键、冲突检查。
- **插件文件夹**：游戏的 `plugins/` 文件夹，放进去的文件开局时按导出的东西自动接上；`lib pull` 把代码拉到这里。🟡 文件夹本身 ✅；导出一个函数时两种渲染方式下报同一个看得懂的错 ✅；但 `lib pull` 拉下来的工厂函数要自己包一行 `export default make()`，现在只是打印提示，没有替 AI 生成（中，要修）
- **插槽表**：`describe().slots` 列出每个插槽插了什么、来自哪个文件、影响了哪些值。✅（也列出引擎自带的模块，读起来有点吵，可以接受）
- 拔掉一个插件，它造成的所有影响自动撤回，不留残渣。✅ 读档之后旧句柄也能撤（守卫测试 `tests/specs/shared-points.mjs`）

## 5. 冲突怎么解决（谁说了算）

- **引擎永远不悄悄替你挑。** 要么有固定规则自动解决，要么开发时报错，让游戏用一行代码决定。✅
- **公共值按层合成**。AI 只需要记三个概念：**基础值**（游戏设定）→ **效果在上面乘**（天气、日落）→ **玩家设置封顶**（只能限制，不能强开）。完整的层是：引擎默认 < 画风 < 游戏 < 效果 < 系统 < 设置 < 调试。✅
  - 设置层只能往下调或关掉：数值只接受 `clamp: { max }` 和 0 到 1 的 `mul`，开关只接受 `set: false`；往上调的写法开发时直接报错，并说该写在游戏层。游戏自己的设置行也用同一条公开写法（`settings.define({ limits })`）。✅（守卫测试 "shared points: ... settings restrict only"）
  - **设置排在系统之上，只能限制**：玩家的限制对系统层（过场、菜单、拍照工具）也有效，玩家关掉的画面抖动、闪光，过场不能再打开。只有调试层能盖过玩家的设置。（2026-11-03 主人定下）✅
- 合作就用 `mul` / `add`，自己说了算就用 `set`。同一层里两个**不同**主人都 `set` 同一个值时，开发时报错，并给出三种可以照抄的改法。✅
- 只有几方真的会一起改的值才是公共值：太阳和环境光、雾、曝光、阴影、后期参数、时间流速。AI 自己的物体、材质、贴图不需要登记。✅
- 游戏第一次设的值被效果改动时，开发时提示一次（例如"你设了 3，下雨时显示 1.8"）。✅
- **角色控制**：每个角色同一时刻只有一个控制者，分四层：平时 < 脚本 < 过场 < 联机。上层接管时下层是暂停，不是取消，结束后自动还回去。✅（机制和共享点分开 🤝，见 P8）
- **按键**：按场合分层；模块只声明需要哪些动作，由游戏绑键；默认只有一套基础键。✅
- **时间**：只有一个计数器，其余全部是它推算出来的视图；子弹时间、加速、暂停用乘法叠加。✅ 绕开共享点的 `time.manual` 已删

## 6. 模块类型

一共 7 种，没有子类型：`world`（数据，不画东西）、`look`（显示）、`actor`（角色）、`rules`（玩法规则）、`ui`（界面）、`net`（联机）、`tool`（一次性工具）。同一类型里的差别靠声明来表达：写了哪些公共值、占了哪个插槽、往哪个材质插槽加了代码、支持哪种渲染方式。✅ `type` 是唯一的分类：外观、界面模块出错只停掉自己，游戏不卡死。

- 越界开发时报错。🟡 开局时查四条（显示类模块不能定义操作、显示和界面模块不能写世界记录、界面模块不能绑键、界面模块不能登记存档，`core/moduleTypes.js`），数据模块画东西由规则 R47 静态检查 ✅；`actor`、`net`、`tool` 三种还没有任何检查，显示类模块登记存档、工具做完不撤回也不拦（小到中，要接着做）
- 模块之间只能用公开接口和事件，不许伸手进别的模块内部；核心不写死具体模块的名字。✅ 规则 R16、R46 检查（也认绕路的路径和动态 `import()`）；核心里只剩 3 处点名模块（content、calendar、flow），每处都在规则 R27 里写了理由 🤝

## 7. 引擎提供什么，AI 写什么

**引擎提供**：three.js 没有、大多数游戏都要、自己写容易出错、而且要和别的系统配合的东西。例如光影的协调（太阳跟着时间走、天气按倍数影响）和工程（大场景分级阴影、阴影更新预算、灯的数量管理、烘焙光照探针）、存档、时间、大世界分块加载、物理、寻路、两种渲染方式下画面一致，以及让 AI 能查问题的状态查询、报错和检查。

**AI 改参数就行**：引擎已经负责，只是数值不同（太阳、雾、曝光、阴影质量、泛光、风、植被密度……）。
**AI 往插槽加代码**：保留引擎的东西，在它上面改一部分（地面笔触、卡通色阶、换云的形状）。
**AI 自己写**：引擎没有的，或者要独特风格的（模型、贴图、自己的材质和 shader、体积雾、手绘风、自己的天空和水）。

注意：有些东西引擎只给**信号**，效果要游戏自己做。例如下雨时地面湿润，引擎只提供"现在雨下得多大"。

**外观接口**：所有外观部件（天空、雾、光、地面、植被、水、后期……）用同一组动词，一共六个：`set`（改数值）、`patch`（换一个命名的钩子）、`add`（往上加一样东西）、`replace`（把部件画的那一个东西换成自己的）、`manual`（引擎不再写，自己管）、`value`（读现在合成出来的值）。模块作者才用的方法在 `part.author` 里，不出现在游戏用的接口上。✅（2026-11-03 主人定下，守卫测试 `tests/specs/look-api.mjs`）

**后期效果只有一个入口**：`look.post.add(...)`，收 three.js 的 Pass、WebGPU 的节点函数或带开关的效果；游戏代码、插件文件夹、画风插件都走它，开关统一用 `look.post.set({ 名字: false })`。✅（2026-11-03 主人定下，守卫测试 `tests/specs/one-post-entry.mjs`）

## 8. 两种渲染方式（WebGL / WebGPU）

- 开局时选，运行中不能切换（three.js 本身也是这样）。WebGPU 不可用时按设置退回，退回时不会崩。✅
- **引擎自己的每个着色器效果都写两份**：WebGL 一份 GLSL，WebGPU 一份节点版（TSL），两份做同一件事。规则 R49 检查引擎的补丁都有 WebGPU 版，缺了不让合并。✅（2026-11-03 主人定下）
- 引擎自带的内容在两边画面一致，用逐像素对比来证明。🟡 地形、植被、水、天空、粒子、泛光 ✅；调色和色调阶段逐像素对比 ✅；描边、景深只比画面平均亮度（相差 3% 以内），环境光遮蔽只确认 WebGPU 上画出来了，两边算法本来不同（WebGL 另画一遍法线，WebGPU 从深度重建）（`tests/specs/post-webgpu.mjs`）——平均亮度证明不了是同一张画面，描边和遮蔽应该补分区域对比（中）；四个材质插槽（灯光声明、光照模型、雾声明、雾）只能用于 WebGL 🤝（WebGPU 的节点材质里没有对应位置，用了会点名报错）；半透明加雾两边一致 ✅；sRGB 图片当背景、开着色调映射时，两种渲染方式、开不开后期都一样 ✅（和普通 three.js 的 WebGL 不同：那边背景不做色调映射，见菜谱 56）；真显卡上跑过性能实测 ✅（2026-11-03，画面对比仍在软件渲染上做）
- AI 的效果只写了一种渲染方式时，开局点名报错。✅

## 9. 数据和代码

- **代码决定"怎么做"，数据决定"有什么、在哪里、是多少"。**
- 设计数据（内容、模板、摆放、画风初始值）放在游戏的文件里，有固定 id，可以用命令写回文件（`threedog content set`、`threedog tune`）。✅
- 运行中的变化存进存档；存档只存和初始内容相比的变化。✅
- 通过 `engine.ops` 定义的玩家操作会进操作记录，可以用于存档、联机、回放、撤销。🟡 直接改世界记录也会进存档，但不会进操作记录 🤝（理由见第 12 节）
- 浏览器里的编辑器（点选、拖动、属性面板、写回文件）是下一版的事。❌（数据层已经有了）

## 10. 让 AI 看得见、查得出

- `describe()`：场景里有什么，每个值是谁写的、怎么合成出来的，谁在控制哪个角色，装了哪些模块、各是什么类型，引擎对 three.js 改了哪些地方（`threePatches`）。🟡 都查得到 ✅；但"谁说了算"分散在好几个表里（见 P8）
- 报错带规则和改法；开发守卫在 AI 写错时当场拦住。✅
- `threedog how` 按任务查文档；AI.md 是"任务 → 接口 → 教程"的索引，有大小上限。✅ 普通 three.js 写法和引擎写法分开标注
- 截图对比、资源浏览（也能画 WebGPU 的节点材质）、性能报告、调参面板、热更新。✅
- 测试运行器不会假通过：没等待的检查、一个检查都没跑的测试项、什么都没匹配到的过滤都算失败。✅

## 11. 衡量

- **易用性 + 对比实测 + 画面实测**：一道难题《一天》，由新引擎和纯 three.js 各做一遍（`docs/testing/usability-tasks.md`）。引擎版本画面明显更差，或者 AI 被引擎挡住，都算引擎的问题。🟡 2026-11-03 新引擎答了一遍《一天》（卡点按根因修了），纯 three.js 答了一遍限时 30 分钟的对比题；两边还没在同一道题上比过，等新引擎版按收窄后的外观接口重跑
- 所有测试结果记在 `docs/testing/runs.md`。✅

## 12. 有意的妥协（复审可以质疑）

| 妥协 | 理由 |
|---|---|
| 引擎对 three.js 的改动一共九处，全部列在 `describe().threePatches`：整页范围的四处（阴影材质、WebGPU 顶点、`Object3D.add/remove` 钩子、新增的 `ShaderChunk.threedog_*` 代码块），按物体或按渲染器的五处（进场景物体的 `material`、被打补丁材质的 `onBeforeCompile`、引擎渲染器的 `render`、游戏灯在亮度为 0 时的 `shadow.autoUpdate`、HLOD 登记物体的 `visible`） | three.js 没有按物体挂钩的办法，自动接入要靠它们；每一处都写明管到哪、关掉后少了什么。七处可以关掉；`ShaderChunk` 代码块关不掉（引擎自己的补丁要用），HLOD 的按登记解除（`remove()`） |
| 四个材质插槽只能用于 WebGL | WebGPU 的节点材质里没有对应位置；用了会点名报错 |
| 开着后期效果时，WebGL 每帧多花约 0.15 ms（画布自带的抗锯齿加上后期链） | 换来的是没开效果的游戏显卡时间省约四成（2026-11-03 协调者接受，`docs/testing/field/2026-11-03-perf.md`） |
| 水只能换材质，网格不能换 | 想整块自己画就不装水模块，水位和水体数据还在引擎里，游泳、浮力照样能读（菜谱 44） |
| 自己写的天空物体引擎认不出来 | 看不出哪个物体是天空；`look.sky.replace(sky)` 一行就接上（菜谱 54） |
| 角色控制、按键场合和共享点是分开的机制 | 它们是"上层暂停下层""遮住下面的"，不是合成出一个数；但查询应该统一（见 P8） |
| 背包、任务自带界面 | `engine.ui.set(名字, false)` 就能关掉换自己的，不卡人 |
| 核心里点名 3 个模块（content、calendar、flow） | 每处都有理由，写在规则 R27 里 |
| 选项表在代码和类型声明里各写一份 | 规则 R6 保证两份一致；以后能从同一张表生成类型最好 |
| 直接改世界记录不进操作记录 | NPC 这类每步都在动的东西，每步记一条操作太重 |
| 渲染方式只能在开局时选 | three.js 本身就是这样 |
| 拉取素材是复制，不是链接 | 每个游戏各改各的，防止所有游戏长得一样 |
